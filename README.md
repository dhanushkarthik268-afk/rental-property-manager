# Rental Property Occupancy and Cash Flow Manager

EECE 7205 Mini Project (Fall 2026) - Dhanush Karthik Ravichandran

A menu-driven C++ console application for a rental business with 6 properties and 126 rooms (monthly rent USD 310-365). It tracks room occupancy and available rooms, handles tenant move-in and move-out, records rent payments, and produces monthly cash flow and pending-rent reports. Data is stored in CSV files so it persists between sessions.

## Data note
The CSV files in `data/` are a **de-identified** dataset that follows the structure of an actual rental business (6 properties, 126 rooms, rent USD 310-365). Property names are placeholders, tenant names are fictional, and amounts are generated within the real rent range.

## Build
Requires a C++17 compiler (g++ 9+ or clang 10+). No external libraries.
```
g++ -std=c++17 -Wall -Wextra -o rental_manager src/main.cpp
```

## Run
Run from the repository root so `data/` is found:
```
./rental_manager              # uses data/
./rental_manager tests/data_large   # any folder containing the same 3 CSV files
```
All input is typed at the menu. Dates use `YYYY-MM-DD`; report months use `YYYY-MM` (sample data covers `2026-09` and `2026-10`).

## Test
```
bash tests/run_tests.sh
```
Runs 19 scripted tests (normal, boundary, invalid, empty, missing-file, CRLF and large-input cases) and prints PASS/FAIL for each. The large dataset is generated by `tests/gen_large.py` on first run. GitHub Actions compiles the program and runs the same tests on every push and pull request.

## Folder structure
```
src/main.cpp            program source
data/                   de-identified sample data (properties, rooms, transactions)
tests/run_tests.sh      automated test runner
tests/gen_large.py      generates tests/data_large (1,260 rooms, ~41,000 transactions)
tests/data_*            test datasets: empty, malformed, CRLF, missing
.github/workflows/      CI build + tests
```

## CSV formats
- `properties.csv`: `propertyId,name,location`
- `rooms.csv`: `roomId,propertyId,monthlyRent,status,tenantName,moveInDate` (status: Occupied / Vacant / Maintenance)
- `transactions.csv`: `txnId,date,propertyId,roomId,type,category,amount,note` (type: RENT / EXPENSE; whole USD)

## Known limitations
- Fields cannot contain commas (quoted CSV fields are not supported); the program blocks commas in typed names.
- Pending rent uses nested loops, O(R x T): about 2.6 s on the 1,260-room / 41,000-transaction test set (unoptimized build). Approach 2 in Iteration 4 addresses this.
- Move-in and payment dates are checked for format and calendar validity only, not against today's date.
- Expenses can be loaded and reported but not yet entered from the menu.
